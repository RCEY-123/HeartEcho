# 心语开发与回归防护

把“本次问题解决”和“已有行为继续成立”同时作为交付条件。本技能约束开发证据，不承诺零缺陷，也不以历史惯例替代用户当前需求。

## 先确定正在修哪一份程序

1. 核对工作区的版本、HEAD、未提交修改和用户实际运行的安装版版本/程序目录/数据目录。只读检查真实数据时输出数量、日期和状态，不输出聊天正文、Key 或登录信息。
2. 合并 PR 或发布前，读取 GitHub 的目标 PR、相关 diff、最近 Releases 和标签。**main、发布标签、安装负载、本地工作区可能不是同一版**：历史版本曾只上传安装负载源码快照，main 曾落后于已发布程序。发现缺少构建工具或回归脚本时补齐正确开发基线，不能以“测试文件不存在”推定通过。
3. 保留本地未提交工作。实现只围绕本次缺陷；全仓格式化、批量 lint 修复、重写默认配置不混入功能修复。新旧规则冲突时以当前用户需求和已验证实现为准；历史阈值不是永久规格。

完成条件：明确受影响版本、实际入口和改动基线；能说明当前用户数据是否真的缺失，而不只是界面没显示。

## 再建立跨模块复现

阅读 [历史故障与依据](references/history.md) 中与本次问题对应的条目，以及 [链路与回归选择](references/regression.md)。为本次修改列出简短影响表：

`入口/生产者 → 持久化及确认位置 → 消费者/API/界面 → 后台任务 → 旧数据/安装版`

给每个受影响节点填写旧行为、新行为、应保持的行为、验证方法。特别核对：

- QQ 私聊、群聊和应用内对话是否经过同一套必要处理；实时事件、历史补收、插件发送是否争用同一条消息的完成状态。
- 旧记忆与新版每日摘要分别写到哪里、被哪些页面和日记/反思任务读取；新开关是否使原定时任务直接返回。
- 通用版与 TB 的运行身份、目录、面板、端口和凭据是否仍独立；显式自定义路径能否原样覆盖升级。

用隔离目录、合成账号和假模型/协议服务运行最小可失败用例。异步问题通过可控制的阻塞点安排“生成中到消息/撤销授权/清空/掉线”，断言最终请求、持久记录和实际投递；只断言 Promise 成功或匹配源码文字不够。保留修复前失败与修复后通过的命令、版本和结果。

完成条件：有一个能捕获用户实际症状的可执行复现；若拿不到现场条件，说明已验证与未验证部分，继续可独立完成的工作，不把猜测写成唯一根因。

## 实现时维持的业务约束

- **原文、回复、记忆是不同状态。** 原始消息独立幂等入库，合并只改变一次模型输入；逐事件记录已答状态。归档确认只能推进到实际交给模型且成功保存的快照，不能拿结束时的全库计数代替；失败、空结果和新到消息继续待处理。
- **身份与清空边界贯穿异步过程。** 保留角色、账号、会话、来源代次；召回、模型队列、发送和写回前复核。清空后不恢复旧消息/附件/目标；删除摘要保留删除语义；手工修改不被在途自动任务覆盖。来源不明的旧记录不靠猜测分配给角色。
- **等待与重连都不是“重跑一遍”。** 连发统一理解，部分已发送、未发送、发送结果未知分别处理；发送结果未知时不盲目重发。WebSocket 接通不等于 QQ 账号在线；仅管理确属本实例的协议进程。
- **功能开关需要相容验证。** 替换记忆后，日记、关系、计划、页面和数据清理仍有明确数据源；暂停/关闭/未授权时行为可解释。当天摘要、日记和反思的生成条件分开说明，缺少材料不补造记录。
- **前端可见即完成的一部分。** 接收成功清空已提交输入，保留后输草稿；页面/角色旧响应不能覆盖新状态。分页、重启重读、超过默认条数的历史及用户明确保存的设置一起验证。
- **升级不带入开发者身份。** 新安装不含测试 Key、私人配置或聊天数据；覆盖升级保留用户自己的 Key。导入成功以运行时确实读到旧角色/原文/记忆/目标为准，不能只以文件复制成功为准。

## 执行回归并交付

先让脚本只输出测试计划，核对是否涵盖影响表中的相邻模块：

```text
python <skill-dir>/scripts/regression_guard.py --root <repo> --files lib/chat.mjs lib/qq-recovery.mjs
python <skill-dir>/scripts/regression_guard.py --root <repo> --area memory --run
```

不传 `--files/--area` 时读取当前 git 改动；`--base <ref>` 比较工作区与指定基线。默认不运行测试、不修改代码。脚本的映射是最低集合，发现新入口须增加针对性用例；不存在的脚本或运行时能力不足会明确报错。

修复后依次检查：原复现、受影响相邻链路、改变的前端实际浏览器流程。修改行为的同时只调整确已变化的测试契约；仍要断言数据隔离、幂等、分页和旧数据兼容。既有失败按同一基线对照，不关闭规则、不删掉用例换绿灯。相关检查已通过后不重复跑无变化的全套测试。

若要构建或上传，继续读 [双版本发布核验](references/release.md)。发布校验失败阻止的是该产物的发布，仍可完成源码修复和诊断；现有用户授权继续有效，不凭本技能增设确认流程。

最终交付说明：根因及触发条件、哪些邻接行为仍成立、实际测试结果及跳过项、数据迁移/补整理方式、安装包与源码对应关系、真实 QQ/模型/干净机未验证部分。测试数量不能代替这些证据。
