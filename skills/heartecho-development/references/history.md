# 历史故障与依据

核对日期：2026-11-04。依据仓库全部六个历史 PR 的正文及文件 diff、dev.1–dev.6 的 GitHub Releases、已验证的 dev.7/dev.8 本地交付记录。上述 PR 的 review 和行内 comment 均为空；未把不存在的评审意见当证据。新任务应检查其后的 PR/版本，旧描述只用于解释回归边界。

## 权限和数据生命周期

- [PR #4](https://github.com/RCEY-123/HeartEcho/pull/4)：控制 API、SSE 与托盘凭据；私人档案绑定账号/用户；清空后的模型、附件、合并、归档、日记等任务用持久代次防止回填。**教训**：改一个入口时检查所有模型/发送路径；清空测试覆盖已开始投递和边界秒新消息。
- [PR #7](https://github.com/RCEY-123/HeartEcho/pull/7)：编辑角色与启用角色分开；新实例保留目标面板令牌，正确分配协议端配置及未运行实例的端口。**教训**：配置保存成功不等于运行实例已使用；继承的环境变量可把子实例指回父数据。
- [dev.1 历史说明](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.1)、[dev.2](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.2)：旧包隐私审查未通过而停止分发；后续去掉自动发现开发者凭据，新增完整迁移和更新。**教训**：发布实际 exe 的内嵌负载必须重审，不能只看源码或临时构建目录。旧包不安全时保留说明，不上传原泄露包。

## 新功能与旧功能的交点

- [PR #9](https://github.com/RCEY-123/HeartEcho/pull/9)：私聊连发独立落库后合并；在途新输入使未发送旧结果失效；问候在发送前复核有效期；群成员分页保存草稿。**教训**：验证最终模型输入里每条原文只出现一次，测试超过旧 pending 容量、发送中途和过期问候。
- [PR #16](https://github.com/RCEY-123/HeartEcho/pull/16)：引入 `hindsight_records`、来源隔离、授权撤销、输入等待、互动额度和独立 TB；当时设计为仅归档前一天。其 `index.mjs` diff 在旧归档与日记定时器中增加了 `if (now.nextMemory.enabled) return`。**教训**：替换一项服务必须检查原有消费者和定时器；“新功能独测通过”不能证明旧数字生命功能还在工作。
- [dev.6](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.6)：QQ 退出后连接状态误报、旧任务拖住重连、事件推送失效，通过按会话历史补收和持久补答回执恢复。**教训**：传输层在线、账号在线、能收新消息、能回新消息需分别验收；重启电脑不是正常恢复方案。
- [dev.7](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.7)：应用内入口绕过连发缓冲；补历史轮询在实时缓冲收集期间把原文当漏消息，导致正常合并后再次逐条回复。**教训**：必须联测“实时接收 + 后台补收 + 发送回执”，重试与去重是两个消费者共同的契约。
- [dev.8](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.8)：新版摘要已存在但旧记忆/数字生命页面没读它；自动日记被跳过；日志仅缓存，聊天历史无翻页；旧归档取200条只给模型末尾80条却确认全会话，新版每天只取末尾120条且不更新。**教训**：分别检查原文、摘要、页面、日记；只确认本批输入，兼顾归档期间新消息、失败重试、手工编辑/删除、当天与前一天及跨午夜。

## 安装和现场环境

- [PR #17](https://github.com/RCEY-123/HeartEcho/pull/17)：Windows 随包 Node 安装器、显式源码清单、备份/回滚和卸载保护；开发预览与真实环境验收边界分开。**教训**：发行需要测试随包运行时、不同版型、旧数据、自定义目录，源码跑通不是安装器验收。
- [dev.3](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.3)：空初始化目录误判为旧数据，导入成功但实际未读取；面板端口冲突；文件提交在加密/重定向目录失败。**教训**：导入应显示并验证来源/目标与实际记录，成功后用运行程序重读，不删源数据作为“修复”。
- [dev.4](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.4)、[dev.5](https://github.com/RCEY-123/HeartEcho/releases/tag/v1.3.0-dev.5)：WS/HTTP 端口和令牌各自对齐；内置 WebSocket 不接受预想的自定义请求头；QQ 自动接入关闭；控制台窗口与共享协议进程管理。**教训**：确认协议端能力、当前账号和配置来源，不反复猜端口或结束共享进程。
- dev.7 将新安装数据和日志改到安装盘，默认旧 AppData 数据校验迁移，自定义路径继续保留。**教训**：不能机械沿用 PR #16 的 AppData 默认值；数据位置一变，媒体绝对路径、TB 设置、更新和卸载都要联测。
- [PR #5](https://github.com/RCEY-123/HeartEcho/pull/5)：ESLint/Prettier 接入记录了既有问题；`APP_JS` 是 `String.raw` 中的浏览器代码。**教训**：外层 Node 语法通过不代表浏览器可运行；比较基线，避免全仓格式化掩盖逻辑变化。

## 仍须现场核验的限制

已发布版本的说明不等于当前任务的验证证据。旧更新器与 GitHub 规范化后的 ASCII 资产名不兼容，dev.8 交付时仍要求手动覆盖；未在本任务修复则在发布说明中保留此限制。真实 QQ/协议端、Docker 全链路、干净 Windows 图形安装和卸载助手清理都曾有未验收项，发布时以本次实际结果逐项更新。
