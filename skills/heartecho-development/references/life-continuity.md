# 生命连续性与维护边界

心语的验收对象是“相处留下了可追溯的变化”：角色能记住明确说过的事实，基于多次经历反思，在之后的对话和日记中自然延续；不是用更长的提示词或更多随机事件证明她有生命。真实意识不作为软件验收承诺。

## 每次代码修改后的检查

先画本次变更经过的生产者、存储、消费者和后台入口，再按 regression_guard 选择邻接测试。对以下链路的修改运行 `node --test tools/life-continuity-test.mjs tools/record-continuity-test.mjs tools/next-version-test.mjs`；修改界面时再运行 `tools/local-chat-browser-test.mjs`。测试缺失、跳过或缺少实际安装器时是未验证，不能用退出码 0 代替通过。

| 情境 | 验收结果 |
| --- | --- |
| “我的生日是3月15号”，随后明确更正 | 每条原文仅评估一次，生日及时持久化；普通聊天无需触发词便可使用最新事实；其他角色、账号、群聊不泄漏 |
| 日程录入生日 | 使用真实表单提交的本地 peerId 与 QQ 分别验证，不能只测空 peerId；日程和聊天使用明确绑定的所有者；无效日期拒绝，删除后停止注入；旧记录不凭昵称猜归属 |
| 多天明确提到作息问题 | 每条信息有原文编号、置信度与重要性；反思至少有多条独立证据，不能用时间戳或同一来源的多个摘要充数；日记能够读取反思 |
| 重启/切换模型/授权撤销 | 相同服务授权跨进程稳定；改变接收方时明确展示重新确认；在途撤销不写回；待处理队列和失败游标可继续 |
| 长消息/一会话模型失败 | 分段后所有原文最终恰好消费，未交给模型的尾段不能推进游标；其他会话可继续；失败或空内容不能标绿成功 |
| 清空/删事实/删摘要/切角色 | 分别验证保留记忆与同时清空；生成中删除不复活；其他角色待办代次仍可用；“忘记”的来源不被后台再次提取 |
| 她的迭代 | 默认关闭，原卡保留；明确评分与证据门槛、频率上限、核心身份优先；不把用户私密信息写进共享角色卡；次数/时间/原因持久化 |
| 身体与生理期 | 明确不可关闭的初始确认；不适用周期可选；同日重读、跨月闰年、时钟回退、离线补记不重抽；模拟状态不成为用户事实或医学诊断 |
| 拒绝/连发/备用接口 | 只有模型明确拒绝才能切备用；取消旧回复不切换；日志分清生成与投递；发送失败不能报“已回复” |

## 维护边界

- `cognition` 管评分和有来源的信息，`archive-batch` 管分段游标，`character-evolution` 管成长评估与原始卡，`body-state` 管日历状态，`continuity-runtime` 只调度，`ui-continuity` 只展示和发起操作。新增能力优先放在对应模块，避免继续扩充主入口和整页字符串。
- 主入口的 `boot-env` 必须先于任何业务模块加载；`paths` 在导入时固定目录。验收实际安装器的 `--selftest` 与 `--instance`，断言原配置和目录完全未被测试写入。只运行 `tools/selftest` 不能覆盖这一入口。
- 新表必须提升数据库版本，并用上一版本的库验证迁移、原文保留与完整性；仅在新建空库上通过不算升级成功。
- 新运行模块同步进入 `tools/payload-source-files.json`。最终验收对象是 exe 内部实际负载，两版各自运行专项测试和浏览器流程。
- 阈值是可解释的产品参数，不是心理学或医学定律。资料来源、适用范围和未验证假设记录在设计文档；不要把模型自报置信度当作真实性证明。
- 对测试修改说明行为契约为何变化，保留原有隔离/游标/异步断言；不得靠删测试、隐藏失败、全仓格式化或再次复制同一套逻辑来交付。

交付记录应能回答：哪条用户原文让她记住了什么，哪个消费者会读到它，重启和清空后会怎样，哪些自然措辞或真实服务尚未验证。技能降低回归风险，不承诺零缺陷。
