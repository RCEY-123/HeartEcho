# 链路与回归选择

先读当前代码，以下是截至 dev.8 的定位图，模块重命名后更新映射。

| 改动区 | 要一起追踪的链路 | 关键观测 |
| --- | --- | --- |
| 聊天/连发/回复 | `onebot` 或 `local-chat` → `chat.receive` → `storage` → 模型/插件 → 投递 → 原事件回执 → `qq-recovery` | A/B/C/D 每条原文入库一次；同一轮模型只看到每条一次；轮询不产生第二份补答；在途追加只撤销未发送结果 |
| 重连/协议 | `ui-app` → API → `health/protocol/onebot` → `qq-recovery` → 聊天/入库 | QQ 在线身份核验、WS/HTTP 各自认证、原合并任务取消、恢复后既能收也能回；一次离开仅解释一次 |
| 记忆/数字生命 | `messages`/`message_origins` → 旧 `memories` 或 `hindsight_records` → API/两种页面 → 日记/反思/目标 | 写入和读取同源；旧模式/本地新模式/Hindsight 开关下日记任务有明确行为；同会话不同日期记录不相互退休 |
| 清空/授权/角色 | scope generation → 排队模型/附件/摘要/发送/外部删除队列 | 撤销后没有过期请求或写回；其他角色/账号/会话保持；来源不明记录不自动注入 |
| 前端 | `APP_JS` → API → 状态缓存/轮询/SSE → DOM | 清空已提交草稿且保留新草稿；慢响应不覆盖新角色；翻页同秒不重复；刷新后仍有数据；浏览器异常为零 |
| 存储/迁移 | installer → settings/`boot-env/paths` → SQLite/日志/媒体 → 导出/升级/卸载 | 新安装与覆盖保留不同的凭据行为；自定义目录不被改回默认；导入后运行程序实际读到旧记录 |
| 发布/更新 | package/version → allowlist/build → exe资源 → Releases资产 → 更新选择/校验/安装 | 两个版型；最终负载与测试源码一致；资产名真实可选；Hash一致；下载或安装失败保留可恢复状态 |

## 组合而非笛卡尔积

按影响表挑选有因果联系的组合，静态文案更改无需跑真实 QQ 或整个安装生命周期。

- 改连发：QQ 与本地私聊，实时收取与轮询同时发生，慢模型/发送等待期间追加，重复事件，部分投递后断线。
- 改归档：当天/昨天/跨午夜，少量新消息/大于分页上限，生成中新增、失败或空结果，编辑/删除/清空期间返回，升级后已有旧自动摘要与手工摘要。
- 改路径或安装：通用/TB，新安装/上一发布版覆盖，自定义数据与日志目录，已存在目标/导入旧目录，媒体旧绝对路径和另一实例数据保护。
- 改 UI：实际点击、重复点击/网络重试、后输草稿、页面切换、重启后读取、记录数量超过初始窗口。Node 外层语法和源码字符串断言仅作辅助。

最低测试集合由 `../scripts/regression_guard.py` 维护。`--area` 可多次指定；`--release` 加入核心跨模块集合与离线自检。默认计划不执行。脚本只使用已有隔离测试，不连接真实账号，不添加固定个人目录，不自动修代码/打包/发布。

## 有效证据的形状

针对一个变更至少记录：故障输入与开关、基线、失败断言、修复后结果、相邻回归、用户可见结果。报告测试失败与 skip 的原因；安装器测试没有传入实际安装包时可能零用例退出0，不能记为通过。

对异步测试用 latch/假时钟控制顺序，校验持久游标和投递次数。模型措辞无需完全固定；同时验证消息合集、角色/账号/会话身份、发送次数及被取消的结果没有落库。用户体验类修改保留实际浏览器步骤。只修复文本时不新增镜像实现的测试。

当主分支缺少 dev.7/dev.8 的回归文件时，选择正确开发工作区或恢复对应测试后再执行；不要退回只跑老测试并称新行为已验证。扩展影响另运行扩展测试；外部真实环境验收须在任务已授权且条件具备时进行。
