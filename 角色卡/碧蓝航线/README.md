## 导入方法

**只导入角色 JSON，不用重新安装应用，也不要使用安装器的「导入旧数据」。** 后者用于迁移整套应用数据，不适用于单张角色卡。

1. 在发布页下载 `HeartEcho-AzurLane-CharacterCards-v1.zip` 并解压。里面的 `characters` 文件夹集中放了 19 张 JSON；只想使用一个角色，可下载该角色独立压缩包。直接在 GitHub 打开 JSON 时请用 **Raw / Download raw file** 保存，不能把网页另存为 JSON。
2. 启动需要导入的那一版心语，在面板左下角查看当前**数据目录**。也可到「运行环境」核对设置；若设置框留空，以左下角实际路径为准。多实例用户应先切到目标实例再查看。通用版与 TB 版需要分别操作，不能凭猜测复制到程序目录。
3. 记下该目录后，**完全退出应用及托盘进程**。建议先用「运行环境」的完整数据导出保存一份现有数据备份，妥善保管，不要上传到公共仓库。
4. 在资源管理器打开刚记下的数据目录，进入其中的 `characters` 子文件夹。如果没有这个子文件夹，先确认是否找错路径，不要选择空目录、安装目录或 `app` 目录来代替。至少完成一次应用初始化后再检查。
5. 将所需的 `azurlane-*.json` 文件复制到这个 `characters` 文件夹中。全部导入时只复制总包 `characters` 里面的 19 个文件；单独导入时复制独立包中的一张 JSON。**不要把外层角色文件夹或 ZIP 直接放进去，不要复制 `index.json`。**
6. 如遇同名文件，选择**跳过**，不要覆盖现有角色。该前缀用于减少与自建卡冲突，但如果以前装过本套角色卡，请先比较内容并备份。不要为解决冲突随意改名：文件名应与 JSON 内的 `id` 一致。
7. 重新启动应用，进入「角色工作室」选择相应角色，检查「外貌特征」等七项均已显示。头像留空，可自行选用你持有的立绘；再到「角色对话」选择角色发送消息。若角色选择器尚未刷新，可重新打开面板。
8. 首次使用先在「模型与资费」填写**自己的 API Key** 并测试模型连接。应用内聊天不需要 SnowLuma；QQ 聊天才需要另行接入协议端。

## 记忆和生命计划怎样衔接

这些卡只提供角色设定，**不会携带、覆盖或创建别人的旧记忆、对话、目标、反思或用户档案**。在「记忆与互动」「记忆」「数字生命」「主动与日程」等页面按应用实际选项配置功能。Hindsight 如需外部服务，应先完成服务接入检查；导入卡片不等于已经部署了记忆服务或自动开启所有功能。

如果是在现有角色上继续旧对话和记忆，不要直接换成新 ID：先备份，再在现有角色的「角色工作室」逐项复制本卡的七项内容及开场白，保留原角色 ID、用户绑定和数据。新卡的 `azurlane-*` ID 会被视为新角色，**不会自动继承旧角色的记忆**。迁移整套数据请使用应用的完整导出与安装器导入流程，并对外部 Hindsight 数据按服务本身的方法另行备份。

## 常见问题

- **导入后看不到角色**：检查是否复制到了面板显示的实际数据目录、是否多套了一层文件夹、是否把扩展名变成 `.json.txt`、是否下载了 HTML 网页、是否完全退出再启动，以及当前是否选中了同一个实例。
- **人设有了，但不回复**：先检查自己填写的 API Key、模型名称与服务地址，再看应用日志。角色卡不含可代用的服务凭据。
- **角色提到不认识的旧事**：本卡未预置个人记忆，检查应用实际提供的历史上下文；未发生的共同经历不应由卡片凭空补全。
- **想改称呼或关系**：在「角色工作室」编辑并保存。本包不锁定字段，也不预设婚姻。独角兽的「哥哥」、塔什干的「同志酱」等均是角色化称呼，可按个人偏好修改。
- **塔什干两张图不一样**：默认外貌以白色冬装图为准；另一张只写入补充设定中的可选换装，不把两套衣服混写。

## 文件与校验

仓库中每位角色独立成一个目录：一张可导入 JSON、一份可阅读 README、一份 SOURCES 来源说明；`index.json` 是目录索引，不是角色卡。总压缩包为方便导入，将全部 JSON 集中到 `characters`；阅读说明仍按角色分类保留。

发布页的 `SHA256SUMS.txt` 可与 PowerShell 的 `Get-FileHash -Algorithm SHA256` 结果比较。所有示例对话、开场白与生活细节均为原创演绎，原游戏文本、角色形象与名称的权利归各自权利人；仅提供同人使用资料，不代表官方背书。
